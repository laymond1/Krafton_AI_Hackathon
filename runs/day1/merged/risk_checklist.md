# Risk Checklist

# Objective

- Use this checklist before committing to a strategy or final submission.

# Facts from Problem

- [x] The raw problem has been reread after the first draft.
- [x] Every hard constraint in the problem is captured in the working brief.
- [x] Output format requirements are explicitly recorded.
- [x] Time or submission conditions are recorded if stated.

# Assumptions

- [x] Every inferred interpretation is listed separately from facts.
- [ ] High-impact assumptions are marked for human review.
- [x] No convenience assumption is being treated as confirmed.
- [x] Ambiguous wording is preserved as ambiguity when evidence is weak.

# Proposed Approach

- [x] The chosen direction fits the 4-hour constraint.
- [x] The approach can be explained clearly in the final submission.
- [x] The approach does not depend on avoidable complexity.
- [x] There is a fallback path if the main plan fails.

# Risks

- [x] The highest-severity risk is named explicitly.
- [x] Reviewer-facing weaknesses are documented.
- [x] Unsupported claims have been removed or labeled.
- [ ] Packaging and formatting risks have been checked.

# Deliverables

- [ ] Comparison table is updated.
- [x] Solution brief reflects the current chosen direction.
- [x] Final submission draft exists in the run folder.
- [x] Supporting notes are enough for a quick human review.

# Immediate Next Actions

1. Fix the highest-severity unchecked item first.
2. Re-run critique or verification if the solution changed materially.
3. Record the final risk posture before packaging.
