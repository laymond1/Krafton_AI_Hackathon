# Risk Checklist

# Objective

- Use this checklist before committing to a strategy or final submission.

# Facts from Problem

- [ ] The raw problem has been reread after the first draft.
- [ ] Every hard constraint in the problem is captured in the working brief.
- [ ] Output format requirements are explicitly recorded.
- [ ] Time or submission conditions are recorded if stated.

# Assumptions

- [ ] Every inferred interpretation is listed separately from facts.
- [ ] High-impact assumptions are marked for human review.
- [ ] No convenience assumption is being treated as confirmed.
- [ ] Ambiguous wording is preserved as ambiguity when evidence is weak.

# Proposed Approach

- [ ] The chosen direction fits the 4-hour constraint.
- [ ] The approach can be explained clearly in the final submission.
- [ ] The approach does not depend on avoidable complexity.
- [ ] There is a fallback path if the main plan fails.

# Risks

- [ ] The highest-severity risk is named explicitly.
- [ ] Reviewer-facing weaknesses are documented.
- [ ] Unsupported claims have been removed or labeled.
- [ ] Packaging and formatting risks have been checked.

# Deliverables

- [ ] Comparison table is updated.
- [ ] Solution brief reflects the current chosen direction.
- [ ] Final submission draft exists in the run folder.
- [ ] Supporting notes are enough for a quick human review.

# Immediate Next Actions

1. Fix the highest-severity unchecked item first.
2. Re-run critique or verification if the solution changed materially.
3. Record the final risk posture before packaging.
